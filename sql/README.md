# SQL scripts

Run these scripts against `data/contact_center.sqlite`, generated by `python src/pipeline.py`.

## Recommended execution order

1. `schema.sql` — documents and initializes the intended tables.
2. `kpi_analysis.sql` — overall KPIs, daily trends, outcome mix, queue performance, hourly analysis.
3. `agent_analysis.sql` — agent performance and volume ranking.
4. `time_analysis.sql` — daily change and cumulative volume using window functions.
5. `reconciliation.sql` — data quality and row-count checks.

## Run with Python's built-in SQLite client

From the repository root:

```bash
python -c "import sqlite3; c=sqlite3.connect('data/contact_center.sqlite'); print(c.execute('SELECT COUNT(*) FROM fact_calls').fetchone()); c.close()"
```

For interactive SQL execution, use DB Browser for SQLite or another SQLite-compatible SQL client. Open `data/contact_center.sqlite` and run the SQL files.

## KPI definitions

- **Offered calls:** count of valid canonical records with `offered_flag = 1`.
- **Handled calls:** count of valid records with `handled_flag = 1`.
- **AHT seconds:** average of talk + hold + after-call-work seconds for handled calls only.
- **Service level:** handled calls with `wait_seconds <= sla_threshold_seconds`, divided by all valid offered calls. Abandoned calls remain in the denominator.
- **Abandonment rate:** abandoned offered calls divided by all valid offered calls.
- **IVR containment rate:** IVR-contained offered calls divided by all valid offered calls.
- Rates use `NULLIF` to avoid divide-by-zero errors.

These are simplified project definitions. Real contact centers may exclude short abandons or use other SLA eligibility rules; such rules must be documented before changing the denominator.

## Important implementation note

The Python loader currently creates the same `fact_calls` and `dim_agents` tables from the validated dataset. `schema.sql` is the explicit schema contract for documentation and fresh database initialization. If you re-run `schema.sql` on an already-populated database, `CREATE TABLE IF NOT EXISTS` will not change the existing table definitions.
